# База данных голубиной фермы

PostgreSQL 17 в Docker. Схема, справочники и тестовые данные создаются скриптами.

## Состав

| Файл | Назначение |
|---|---|
| `src/main/resources/schema.sql` | Создание схемы (DDL). Сначала удаляет таблицы, поэтому его можно запускать повторно |
| `src/main/resources/seed.sql` | Начальное наполнение справочников: породы, сотрудники, препараты, вольеры, корма |
| `scripts/generate_test_data.py` | Генерация тестовых данных на Python |
| `scripts/recreate_db.sh` | Полное пересоздание БД одной командой |
| `docker-compose.yaml` | Контейнер PostgreSQL; при первом запуске сам выполняет `schema.sql` и `seed.sql` |

Параметры подключения: `localhost:5432`, база, пользователь и пароль — `chicken-farm`.

## Требования

- Docker с Docker Compose;
- Python 3.10+ (зависимость `psycopg` скрипт пересоздания ставит сам в `.venv`).

## Создание и пересоздание БД

```bash
./scripts/recreate_db.sh
```

Скрипт запускает контейнер, выполняет `schema.sql` и `seed.sql`, затем генерирует тестовые данные.
Все существующие данные при этом удаляются. Время работы — несколько секунд.

### Только тестовые данные

Генератор можно запускать отдельно. Он очищает и заново заполняет только тестовые таблицы,
справочники не трогает:

```bash
.venv/bin/python scripts/generate_test_data.py
```

### Полный сброс вместе с томом Docker

```bash
docker compose down -v
docker compose up -d
```

На пустом томе PostgreSQL сам выполнит `schema.sql` и `seed.sql` (папка `docker-entrypoint-initdb.d`).
Если том уже существует, эти скрипты не выполняются — используйте `recreate_db.sh`.

### Вручную из IntelliJ IDEA

Откройте `schema.sql`, затем `seed.sql`, выберите подключение `chicken-farm@localhost`
и выполните весь файл (Ctrl+A, Ctrl+Enter). После этого запустите генератор.

## Тестовые данные

Генератор читает справочники из БД и заполняет остальные таблицы случайными данными.
Данные проходят все ограничения схемы, а также:

- птенцы младше родителей, вылупились из яиц кладки своей пары и наследуют породу одного из родителей;
- каждый год есть близкородственные пары (брат и сестра по отцу), а у части пар нет разрешения (`approved_by` пуст);
- часть пар 2025 года не распалась к концу года (`end_date` пуст или в 2026 году);
- все события птицы (перемещения, осмотры, вакцинации, вылеты, передача) — после её рождения;
- перемещения идут цепочкой: птица уходит из того вольера, куда переехала в прошлый раз;
- корма списывается не больше, чем есть в партии; статус партии соответствует остатку и сроку годности.

Объём задаётся константами в начале скрипта (`FOUNDERS`, `PAIRS_PER_YEAR`, `FLIGHTS` и т.д.).
По умолчанию получается около 470 птиц, 180 племенных пар, 1200 перемещений, 900 осмотров,
1500 записей об участии в вылетах и 670 списаний корма. Благодаря `random.seed(42)`
при каждом запуске данные одинаковые.

Вакцины генератор отличает от лечебных препаратов по названию: названия вакцин в `seed.sql`
начинаются со слова «Вакцина».
